# ADR-0006 — شناسهٔ اصلی: ULID

| متادیتا | مقدار |
|---|---|
| شماره | ADR-0006 |
| وضعیت | **Accepted** |
| تاریخ | 2026-10-01 |
| سطح اثر | Data |
| مرتبط | DOC-082، DOC-086 |

## ۱. زمینه
باید نوع شناسهٔ اصلی جداول تعیین شود. Auto-Increment سنتی است اما برای معماری توزیعی
و جلوگیری از نشت اطلاعات مشکل دارد.

## ۲. تصمیم
شناسهٔ اصلی پیش‌فرض: **ULID** (`char(26)`) به‌جای Auto-Increment. برای جداول با حجم خیلی
بالا و نیاز به sort، `bigint` هم مجاز است.

## ۳. گزینه‌ها
| گزینه | مزیت | عیب |
|---|---|---|
| Auto-Increment | ساده، compact | نشت اطلاعات، وابسته به DB مرکزی |
| UUID v4 | توزیعی | ترتیب تصادفی → ایندکس ضعیف |
| **ULID (انتخابی)** | توزیعی + مرتب + compact | ۲۶ بایت (بزرگ‌تر از bigint) |
| Snowflake | مرتب، compact | نیاز به worker id |

## ۴. دلایل
- **توزیعی**: بدون هماهنگی مرکزی تولید می‌شود (برای microservice حیاتی).
- **مرتب زمانی**: prefix زمانی دارد → ایندکس B-tree کارآمد.
- **بدون نشت اطلاعات**: تعداد رکوردها لو نمی‌رود (برخلاف auto-increment).
- **قابل حمل**: در URL امن است.

## ۵. پیامدها
- `Support\Id\Ulid` خودنوشته (DOC-082).
- `char(26)` با collation مناسب.
- `Model::$keyType = 'ulid'`.

## ۶. اعتبارسنجی
- 🧪 ULID monotonic در یک میلی‌ثانیه.
- 🧪 index performance در ۱M رکورد.
