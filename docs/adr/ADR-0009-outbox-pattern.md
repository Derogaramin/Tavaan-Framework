# ADR-0009 — Outbox به‌عنوان الگوی پیش‌فرض رویداد ناهمزمان

| متادیتا | مقدار |
|---|---|
| شماره | ADR-0009 |
| وضعیت | **Accepted** |
| تاریخ | 2026-10-01 |
| سطح اثر | Engine (event) |
| مرتبط | DOC-023، DOC-033 |

## ۱. زمینه
انتشار رویداد بعد از commit تراکنش می‌تواند گم شود (اگر publish شکست بخورد).
انتشار داخل تراکنش هم مشکل دارد (اگر تراکنش rollback شود ولی رویداد رفته باشد).

## ۲. تصمیم
**Transactional Outbox** به‌عنوان الگوی پیش‌فرض برای رویدادهای بین‌ماژولی/بین‌سرویسی:
رویداد در همان تراکنش تغییر Aggregate در جدول `tvn_outbox` نوشته می‌شود، سپس یک
Relay آن را به مقصد می‌رساند (At-Least-Once). مصرف‌کننده با `tvn_inbox` و Idempotency Key
از پردازش دوباره جلوگیری می‌کند.

## ۳. گزینه‌ها
| گزینه | مزیت | عیب |
|---|---|---|
| Publish مستقیم بعد از commit | ساده | گم‌شدن رویداد در صورت شکست |
| Publish داخل تراکنش | اتمیک با DB | اگر تراکنش rollback شود، رویداد نادرست |
| **Outbox (انتخابی)** | اتمیک + قابل اتکا | جدول اضافه، Relay |
| CDC (binlog) | بدون جدول | پیچیدگی زیرساخت |

## ۴. پیامدها
- جداول `tvn_outbox` + `tvn_inbox`.
- Relay با `FOR UPDATE SKIP LOCKED` برای workerهای موازی.
- حالت `inline` برای مونولیت (تأخیر ~۰).

## ۵. اعتبارسنجی
- 🧪 rollback → ۰ رویداد منتشر (AC-EVT-05).
- 🧪 ۳ relay موازی → هر رویداد یک‌بار (AC-EVT-07).
