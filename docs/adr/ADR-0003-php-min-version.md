# ADR-0003 — حداقل نسخهٔ PHP = 8.2

| متادیتا | مقدار |
|---|---|
| شماره | ADR-0003 |
| وضعیت | **Accepted** |
| تاریخ | 2026-10-01 |
| سطح اثر | Global |
| مرتبط | DOC-010 |

## ۱. زمینه
باید کف نسخهٔ PHP تعیین شود. صورت مسئله «حداقل 8.2» و «جلوگیری از Deprecated» را خواسته است.

## ۲. تصمیم
حداقل نسخهٔ **PHP 8.2.0**. کد باید روی 8.2/8.3/8.4 بدون `E_DEPRECATED` اجرا شود.

## ۳. گزینه‌ها
| گزینه | مزایا | معایب |
|---|---|---|
| PHP 8.0/8.1 | پوشش بیشتر سرورهای قدیمی | نبود readonly class، DNF types، features منسوخ |
| **PHP 8.2 (انتخابی)** | readonly class، DNF، null/false/true types، ثبات | سرورهای خیلی قدیمی پشتیبانی نمی‌شوند |
| PHP 8.4 | جدیدترین (property hooks) | پذیرش کم در production |

## ۴. دلایل
- `readonly class` (8.2) برای Value Objectها حیاتی است.
- DNF Types برای قراردادهای دقیق.
- حذف کامل ویژگی‌های منسوخ و استفاده از مدرن‌ها.
- تعادل بین پذیرش production و قابلیت‌ها.

## ۵. پیامدها
- قابلیت‌های 8.3/8.4 (مثل property hooks، `json_validate`) فقط با `PHP_VERSION_ID` check + Fallback (موتور `compat`).
- CI matrix روی 8.2/8.3/8.4.
- ممنوعیت `if (PHP_VERSION_ID < 80200)` — 8.2 کف مطلق است.

## ۶. اعتبارسنجی
- 🧪 CI روی هر سه نسخه سبز، صفر Deprecated (`AC-CI-03`).
